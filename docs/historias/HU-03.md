# HU-03 — Evaluación de estado de operatividad

## Historia de usuario

Como **turista**, quiero **verificar si un sitio patrimonial está abierto según la hora actual y su horario de atención**, para **planificar mi visita y evitar encontrar el sitio cerrado**.

**INVEST:** Independiente (solo necesita un horario y una hora), Negociable (formato de respuesta ajustable), Valiosa (evita viajes en vano), Estimable, Pequeña (una comparación de horas), Testeable (tabla de casos).

## Reglas confirmadas (tabla de pruebas del equipo)

- `estaOperativo(horaActual, apertura, cierre)` devuelve `true` si `apertura <= horaActual <= cierre`. **Ambos extremos están incluidos.**
- Fuera del rango devuelve `false`.
- Casos con horario 09:00 a 17:00: 10:00 → true, 18:00 → false, 09:00 → true, 17:00 → true.

**Regla de un documento anterior del equipo (criterio de aceptación CUS-03):** un formato de hora inválido (por ejemplo 25:00) o un valor negativo lanza `InvalidArgumentException`. No aparece en la tabla de esta historia; ver P1.

## Pendientes de confirmar (el agente debe preguntar, no decidir)

- **P1.** ¿Sigue vigente que un formato inválido (25:00, texto, valores negativos) lance excepción? Hay que agregarlo a la tabla de pruebas si es así.
- **P2.** ¿La hora actual llega como parámetro (como en la tabla) o se toma del reloj del servidor? Si es del reloj, ¿con qué zona horaria (por ejemplo, la de Perú)?
- **P3.** Formato de las horas: ¿texto `HH:MM` en 24 horas?
- **P4.** ¿Qué pasa con horarios que cruzan la medianoche (apertura 22:00, cierre 02:00)? La tabla no los cubre.
- **P5.** ¿De dónde salen la apertura y el cierre de cada sitio: base de datos o datos simulados?
